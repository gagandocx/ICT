# HTF range wiring, daily P&L reset fix, dead code removal (v3)

This commit completes the premium/discount filter integration and resolves the remaining v2 issues. The live loop now fetches D1 candles at startup and on day-change to derive the HTF swing range, passing it to the entry model via `set_htf_range()`. The backtester builds daily OHLC from 1m data and computes a rolling 20-day swing range per day boundary. Daily P&L tracking uses a local `day_start_balance` variable initialized to `None` and set on first successful account info fetch, eliminating the function-attribute persistence and desync issues. The dead `get_open_positions()` call and unused `known_tickets` set are removed.

**Watch for:** The silent connection death problem raised in v2 remains unaddressed — `connector.connected` is only set to `False` by the wrapper's own `disconnect()`, so a dead socket won't trigger the reconnection path (likely, non-blocking). The backtester's first few days never receive an HTF range since `update_htf_range` requires at least 3 prior days of OHLC (possible — depends on dataset length, unlikely to matter for multi-week backtests).

**Verdict**: APPROVED

## High-level view

The premium/discount filter is now reachable in both execution paths. In live mode, `refresh_htf_range()` fetches 20 D1 candles with `lookback=3`; in the backtester, `update_htf_range()` derives swing points from up to 20 prior daily bars with `lookback=2`. The lookback asymmetry means backtested signal filtering won't perfectly match live filtering — a minor discrepancy but worth noting for anyone comparing results across modes.

The silent connection death issue from v2 is an operational concern rather than a correctness bug — the bot handles `get_candles()` returning `None` without crashing, it just silently stops trading. This is a robustness improvement for a future pass, not a shipping blocker.

## HTF range derivation asymmetry between live and backtest

The live path uses `lookback=3` for `detect_swing_points` on D1 data (20 candles), while the backtester uses `lookback=2` on daily OHLC. Backtested signal filtering won't perfectly match live filtering — a swing point detected live at `lookback=3` requires a deeper confirmed reversal than `lookback=2` in backtest. The difference is minor (both are small lookback windows on daily data) but anyone tuning strategy parameters against backtest results and deploying live should be aware the premium/discount gate has slightly different sensitivity.

## Backtester cold-start on short datasets

The `update_htf_range` function requires `len(past_days) >= 3` before it sets any range. For the first 3 calendar days of any dataset, the premium/discount filter is inactive and all signals pass through unfiltered. On datasets shorter than a week, the filter may never activate — worth documenting for users running quick validation backtests.
